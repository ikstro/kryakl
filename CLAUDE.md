# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Kryakl (Крякл in the Ukrainian and Russian interface and pages; "Your language. Your shortcut."; called Krya until 0.15 (2026-11-03), Altype until 0.11 (2026-10-30), 2Talker until 0.3, tu-talk before that): a Windows tray app (Electron) that translates a picked text offline and reads the English aloud; it also translates any text both ways like DeepL, reads text from the screen, and switches and fixes keyboard layouts (in place of EveryLang). A sibling of the Language Tutor in `ikstro/cc-translator` (`E:\Cursor\Plugin\CC-translator`): the card's webview, the natural voice, the system voice and the word dictionary were copied from its `panel/` and adapted; the two repositories do not share code at build time.

```

npm test                          # vitest
npx vitest run src/translate.test.ts
npm run typecheck
npm run build                     # esbuild: dist/main.js, preload.js, mt-worker.js, voice-worker.js, kbd-worker.js, field-worker.js; media/card.js, app.js, tray.js, menu.js; codicons into media/
npm start                         # build + electron .

npm run icons                     # Kryakl's icon K3, the duck {•> on a black tile, white braces and eye, a yellow beak (build/icon.svg's shapes, drawn on a canvas under Electron) → build/icon.png (512), build/icon.ico (16–256; 16 set pixel by pixel, the tile's corners too, `TILE_16`), media/icon.png (128); the tray's T2 {•> for a light and a dark taskbar, each also paused (45 %), and the red record dot → media/tray-{light,dark}[-paused].png, tray-recording.png, each with @2x (16 set pixel by pixel, 32 the same pixels doubled; the dot drawn on its own 32 grid)
npm run models                    # scripts/build-mt.mjs: src/mt-manifest.json + vendor/bergamot from Mozilla
npm run glyphs                    # scripts/build-glyphs.mjs: the Lucide icons the pages use (lucide-static, MIT) → src/webview/lucide.ts
npm run shots                     # scripts/shots.mjs: every page, the tray panel and the badge pictured offscreen → .cache/shots/*.png (build first; runs beside the installed Kryakl)
node scripts/idle-check.mjs [min]   # waits (5 min by default), then lists Kryakl's processes and memory and the engine's loaded models; exit 1 when anything of Kryakl's is still on the graphics card
node scripts/build-site.mjs       # the landing's Ukrainian and Russian pages from site/index.html → site/uk/, site/ru/ (--check: what stays English)
node scripts/build-words.mjs      # media/layout/{en,ru,uk,bg,mk,el,he,ar,fa,ka}.txt: the layout fixer's word lists (FrequencyWords; it has no be, kk, hy, and its sr is Latin)
cd engine; uv sync --extra speakers-gpu --group dev   # the speech engine for development, in engine/.venv
npm run test:engine               # engine/tests in engine/.venv (uv run --no-sync); the release workflow runs it on the core part
```

One Kryakl at a time, always: `main.ts` takes the single-instance lock on Kryakl's own folder before anything else, so a second start (installed, `npm start` or a test run) hands its arguments to the first and quits; an Altype still running (an older install, whose lock is on its own folder) is named in a message and Kryakl quits (`oldAppRunning`), as its folders are about to move. A test run (`KRYA_TEST_HOME=<folder>`: its own settings and speech engine folder, `KRYA_TEST_PORT`, 8797 by default, Windows' startup list left alone, nothing moved from the old folders; the `ALTYPE_*` names still read) therefore needs the installed Kryakl quit first.

Uninstall (`build/installer.nsh`, `customUnInstall`) asks once whether the data goes too: Yes removes `%APPDATA%\Kryakl` (and `Altype`, `2Talker`, `tu-talk`), `%LOCALAPPDATA%\Kryakl` (the speech engine; and `Altype`) and `Documents\Kryakl` (transcripts; and `Altype`); No keeps everything for a later install; an update (`--updated`) and a silent uninstall never ask or delete; notes in the knowledge base are never touched.

Release: bump `version` in package.json, commit, tag `v<version>`, push the tag. `esbuild.mjs` stamps the main bundle with `KRYA_BUILD` (time, git commit, changed); About, Settings › Version and the tray show the version, and a run from source says "dev" and when it was built (`buildText`), so it is never taken for the last release. `.github/workflows/release.yml` builds and tests on windows-latest with a read-only token (`npm run dist -- --publish never`), then a second job, which runs no npm or PyPI code, drafts the GitHub release with the installer (`gh release create --draft`, `--prerelease` for a tag with a dash); publishing the draft is the owner's step. Actions are pinned by commit, checkout keeps no credentials. Kryakl does not update itself (2026-10-30, the owner: "обновление только через GitHub"): electron-updater and `src/update.ts` are gone; Settings › Version and About link to the releases, and the installer installs over the old version. The installer is unsigned.

A shell started from VS Code or Claude Code may carry `ELECTRON_RUN_AS_NODE=1`; Electron then runs as plain Node and `electron.app` is undefined. Run with it unset (`env -u ELECTRON_RUN_AS_NODE …`).

## Architecture

Main process (`src/main.ts`): tray, the card window, the app window, flows. `%APPDATA%\Kryakl\`: `settings.json` (`settings.ts`), the person's lists and logs; `words.json` (`words.ts` `WordStore`: the notebook, one entry per dictionary form; `ankiTsv` for Anki's import); `adoptOldFolder` moves them over from `%APPDATA%\Altype` (and `2Talker`, `tu-talk`) once, item by item (`oldfolder.ts ITEMS`: the app's own files, never Electron's caches; `altype.log` becomes `kryakl.log`). **Everything downloaded is in one folder**, `%LOCALAPPDATA%\Kryakl` (never roamed): `models\<code>\` (Firefox's translator), `voice\` (Kokoro), `dict\`, `translate\`, `speech\`; it was `%LOCALAPPDATA%\Altype` until 0.11 and moves over at start, whole when Kryakl has none yet, else part by part (`adoptLocalFolder`); the speech engine's Python remembers its place by absolute paths (`env\pyvenv.cfg` `home`, the junction uv makes for the minor version in `python\`), which `repairSpeech` rewrites (the junction by `unlinkSync`: Electron 45's Node refuses `rmSync` on a junction, which left 0.15.0's moves on Krya's folder; `healSpeech` points a junction that leads nowhere at the folder beside it at every start), so it runs as it was with no new install (its packages' hard links into uv's cache move with it); uv 0.13's `env\Scripts\python.exe`, the one Kryakl runs, keeps its Python's absolute path inside the file (`UV_PYTHON_PATH`), so a launcher that names an old name's folder (`SpeechPack.moved`) is made again at the engine's start by `uv venv --allow-existing` (`relocate`: a second, packages kept, nothing downloaded; once a run; should uv fail, the environment is synced again from the cache, the models kept; 2026-11-03: 0.15.0 on the owner's laptop never started the engine, "uv trampoline failed to spawn Python child process", and dictation said "The speech engine is starting" at every press; it now says when the engine gave up, `dict.engineDown`, a click opening Report a problem); the first three lived in `%APPDATA%` until 0.10.1 and move over once at start (`oldfolder.ts moveDownloads`); a part that cannot move is used where it is (`partDir`, `localPart`, `downloads`; the engine is told its folder, `KRYA_SPEECH_DIR`); a program run from inside the old folder keeps its files in use (the speech engine's python.exe and uv.exe, llama-server.exe, left by Altype or a run from source), so while the old folder holds a part Kryakl's has not (`hasToMove`), those programs are stopped first (`freeFolder`: Windows' list through PowerShell `-EncodedCommand`, CIM `Win32_Process.ExecutablePath`, `holdersIn` picks those under the folder, never Kryakl or Altype.exe, which `oldAppRunning` waits for), and `kryakl.log` says what was stopped and what stayed and why (`leftIn`, `whyLeft`: "left in …\Altype: speech (a file in it is in use by python.exe)"; a part Kryakl has its own copy of stays, unused). The old names' updater downloads (`%LOCALAPPDATA%\altype-updater`) go. Closing the card (`hideCard`: Esc, ✕, a click elsewhere) also sends `stop` to the card, which plays the natural voice's audio itself. Esc and ✕ (`closeCard`, 2026-10-30) first give the keyboard back to the window in front when the card opened (`cameFrom`; a Translate card from a selection, its `pasteTarget` window and field, as Paste does), as a hidden card leaves Windows to bring up a window of its choosing; a click elsewhere only hides it.

- **Selected text**: `winclip.ts` registers the card window as a clipboard listener (user32 through koffi; `WM_CLIPBOARDUPDATE` via `hookWindowMessage`). `clipboard.ts` `DoubleCopy`: two changes 40–650 ms apart with Ctrl held = a request (`doubleCopy` setting); changes closer than 40 ms are one copy announced in several formats. Copies made inside the focused card are ignored. The selection shortcut (`selectKey`, none by default) waits until its keys are let go, presses Ctrl+C in the program in front (`pressCopy`, `keybd_event`) and takes the next clipboard change within 2 s (`COPY_WAIT_MS`, `copyWanted`; 600 ms until 0.10.1, too short for a busy VS Code, whose late copy was thrown away as "Nothing was copied"; `kryakl.log` says "copy: came in N ms from <exe>" or "copy: nothing in 2000 ms"; the fix key's `convertOver` waits as long). `registerShortcuts()` registers it and `snipKey`; either may be empty.
- **Screenshot**: the snip shortcut (`snipKey`, default Ctrl+Alt+S) opens `ms-screenclip:` (Windows' snipping overlay); the next picture on the clipboard within two minutes is the snip (`clipboard.read()`, `image/png`; Electron 45's clipboard API is async). `ocr.ts` runs `Windows.Media.Ocr` through Windows PowerShell (`-EncodedCommand`, never `-ExecutionPolicy`): every installed engine of the person's languages reads the snip (their own first, English last; small text, lines under 20 px, scaled up twice first: three times read worse), and `ocrpick.ts` `pickLines` takes each line from the reading that reads it best (`lineScore`: words in the person's lists count for it; Cyrillic or Greek look-alikes between Latin words, a bracket by a letter, mixed scripts against it), then its doubtful words from another reading where the line reads better (`mergeLine`). One engine is not enough (2026-10-29): the Russian one wrote English "can", "a", "gpu" as "сап", "а", "дри", which the direction rule then sent into English; `ocrtext.ts` joins lines into paragraphs by their boxes. Two purposes (`Purpose`), each from the selection or the screen: **listen** (the card above: `doubleCopy`, `selectKey`, `snipKey`) and **translate**, the translator (`translateKey` with `useSelection('translate')`, `textKey` with `snip('translate')` → `readScreenText`): the same card in kind `translate` or `text`, the text as it is (editable, its English words clickable), Copy, From ⇄ To over the 32 languages, translated at once (`translateWindow`, `translateTextCard`). `translate.ts` `languageOf` guesses the source (a script of one language; letters of one language: қ… kk, і/ї/є/ґ uk, ђ… sr, ы/э/ё ru, پ… fa; else the language with most of its 200 common words in the text, `media/lang-words.json`; a short text: English by `media/layout/en.txt`), the vote and the English rule only among the languages the person uses (`pool`: `settings.ts myLanguages`: their own, English and `languages`, chosen in Settings; a script none of them uses falls back to all 32), `targetFor` the target (the person's own, English from it), `translatePlain` translates through English when neither side is. No Translate button: an edit is translated again after a 700 ms pause (the last translation shown faded meanwhile), a language picked at once. Swap (framed, after the languages) swaps them and, a translation in, makes it the text (DeepL's way). Paste (blue; Enter on the window or in the field, Shift+Enter a new line; a translation still coming is pasted once in; only for a selection, `canPaste`): `pasteTranslation` brings back the window the text was selected in (`focusWindow`, `SetForegroundWindow` while the card is in front), hides the card and pastes over the selection through the clipboard. Nothing of Kryakl's is left on the clipboard (2026-10-29): every borrowing (the selection keys, Paste, Translate in place, the fix key over a selection, a dictated phrase, Chrome's address, the snip) goes through `clipguard.ts` `ClipboardGuard` over `winclipboard.ts` (user32 through koffi, the card's window owning the writes): `hold` keeps every format there (copied files and Office's formats too; GDI handles and private formats are not kept), one snapshot for a run of actions close together (the fix key pressed twice); Kryakl's writes and its putting back carry `ExcludeClipboardContentFromMonitorProcessing`, `CanIncludeInClipboardHistory` = 0 and `CanUploadToCloudClipboard` = 0, so Win+V and the cloud clipboard never see them; a text to paste is only promised (`writeText(…, paste)`, Windows' delayed rendering: `SetClipboardData` with no data, handed over in `WM_RENDERFORMAT` through the card window's hook, `watchRendering`), and `ClipboardGuard.read` decides who gets it: before Ctrl+V (`pasted`) nobody is pasting, so a program asking then is one watching the clipboard against the history marks and gets nothing (2026-10-30: Viber reads every change within a millisecond, which hid the paste's own read), after it the paste's program does, and that read is the signal; `release` puts it back `AFTER_READ_MS` (150) after it, `READ_WAIT_MS` (2.5 s) at most when no read is seen (a fixed 500 ms before let a slow program paste the old content), only while the clipboard's sequence number is still one of Kryakl's (`write`, `claim` for a copy Kryakl pressed) — a copy the person made meanwhile stays — and writes nothing when nothing changed; another program holding the clipboard is waited for; quitting puts back at once (`flush`, before the windows close). The listener skips Kryakl's own changes by their number. A selection key that finds nothing copied waits `LATE_COPY_MS` for a late copy (Ctrl up) to take back too; the snip puts back what was there once the picture is read, and a copy without a picture ends the wait for it (Ctrl+C twice works again at once). Windows' own snipping tool still puts its picture in Win+V. Ctrl+C twice is the person's own copy.

Same-script natives (German…) are treated as English source for now. `splitText` + `translateLines`: when no sentence goes into English (`englishReady`), `main.ts` `translateInto` shows the English at once (`done` with the translation `translating`/`downloading`) and the card starts reading while the translation comes. `render.ts` writes two halves as plain paragraphs, one per line (no markdown: a picked text is not markdown; `sentences.ts` `unwrapLines` first joins lines broken mid-sentence: a line ending in a letter, digit, comma or hyphen followed by one starting in lower case without a list marker; a list item goes on so too): `englishHtml` (`span.s[data-i]`) and `translationHtml` (`span.t[data-i]`).

- **Check my English** (2026-10-30, `checker.ts`): the person's English corrected by their local model (`settings.model`, `createChecker`'s `model()`: Accurate, Gemma 4 E4B, 5.2 GB, or Most accurate, Gemma 4 12B, 7 GB; Apache 2.0), the same file and the same `LlamaServer` as the levels, so translating and checking never load a model each (measured: loaded once in 3.5 s, then a check 0.9 s and a translation with no reload): `/v1/chat/completions` with thinking off, `temperature` 0 and llama.cpp's `json_schema` forcing `{corrected, note}`; `checkPrompt(native)` asks for real mistakes only (no rephrasing, code and names left alone) and one note in the person's language on the main mistake ("made → make: …"). ## Since 2026-11-12: dictation quality

Over the paragraphs of the speech engine above where they differ. Every number in `docs/speech-quality.md`.

- **A bench kept in git** (`engine/quality/`, `npm run quality:speech -- --help`): FLEURS read speech (ru, uk, en, the test split, into `.cache/speech-quality/`) and the owner's own reading (`--sets own`, `.cache/speech-quality/own/`, never in git), under five conditions (`conditions.py`: clean, fan, babble, far, quiet), through the real code: a whole phrase (`asr.recognizer(...).dictate`) or a streamed dictation (`stream.Session` fed in real time, `--mode stream`); word errors (`wer.py`, tested in `test_wer.py`), phrases in the wrong language, seconds a phrase, the wait after the key. `--set module.NAME=value` tries a lever; `report` appends a run's table to the doc. - **No style sentence in dictation** (`asr.STYLE`, recordings only): given it, turbo on a streamed 20 s dictation of three sentences wrote only the last one, and the small models wrote the sentence itself on quiet sound. The prompt is the text said before, alone.
- **Quiet sound raised** (`audio.lift`, `LIFT_BELOW` −20 dBFS, to −6, 30 dB at most), before Silero looks for speech (`_speech_only`, `stream.speech_in`): dictation has no gain control since 2026-11-10, and faint or far speech was missed whole. 7 % fewer wrong words with turbo, 5 % with small and Parakeet.
- **Parakeet's floor** (`asr.PARAKEET_FLOOR` −0.5, its tokens' mean log-probability): under it the text is dropped; on faint speech it made up English ("Yeah, I don't know" for distant Russian). Phrases in a wrong language 55 → 5 of 600; the right-language ones dropped had 82 % of their words wrong.
- **Murmurs** (`phantoms.MURMURS`: "you", "come on"): a lone one is never a dictated phrase (turbo writes it over a raised breath), in a recording only over silence.
