# Крякл для Mac: план (2026-11-17)

## Для меня

**Зачем.** Дать ребятам с Mac ту же программу, что есть на Windows. Сейчас примерно четверть кода (клавиатура, буфер обмена, чтение выделенного, скриншоты, установка моделей) написана только под Windows.

**Ветки.** Одна ветка и один код, не две. Общая часть (перевод, карточки, разговор, проверка английского, окна, настройки) остаётся одна. Всё системное получает две реализации, для Windows и для Mac. Каждый релиз собирает два установщика с одним номером версии. Две ветки разошлись бы за месяц, и каждую правку пришлось бы делать дважды.

**Решено вами.** Mac на M1 и новее. Подпись Apple с вашего оплаченного аккаунта: Крякл открывается как обычная программа, без обходов. В первой сборке всё как на Windows. Промежуточных сборок ребятам нет, я проверяю всё возможное на Mac-серверах GitHub. В окнах три кружка слева.

**Что будет иначе на Mac** (решил я, по правилам системы):
- Нужна macOS 14 или новее: на более старой не ставится распознавание речи.
- Клавиши: Cmd вместо Ctrl («Cmd+C дважды»), Option вместо Alt. Клавиш Print Screen и Pause на Mac нет, человек назначает свои.
- Значок живёт в строке меню сверху. Запись всего экрана останавливается кликом по нему, как у самой macOS: полоску управления Mac не умеет прятать из видео.
- Первый запуск получает шаг «Разрешения», до пяти штук: управление клавиатурой, слежение за клавишами, запись экрана, микрофон, запись звука системы. Запись экрана macOS 15+ переспрашивает раз в месяц сама.
- Модели: память у Mac общая, совет по её объёму: 8 ГБ — Быстрый, 16 ГБ — Точный, от 24 ГБ — Самый точный. Уточню по замерам ребят.
- Текст с экрана читает распознаватель Apple. В скриншоте подсвечивается окно или страница, «панелей внутри окна» на Mac нет.

**Риски.**
- Я пишу вслепую. Серверы GitHub проверят механику (клавиши, вставку, скриншот, запись), но у них 7 ГБ памяти и нет микрофона. Только человек проверит: настоящие модели и их скорость, микрофон, звук системы, два монитора. После первых отчётов почти наверняка нужна вторая сборка.
- Первый шаг переносит системный код Windows за общую границу и задевает почти все функции. Перед следующим релизом Windows нужна ваша ручная проверка шести главных сценариев.
- На Mac хуже, чем на Windows, могут работать: возврат в окно после «Вставить» (система может не отдать фокус), исправление раскладки в терминалах и играх, а также всё клавиатурное, пока где-то открыт ввод пароля (система прячет клавиши от всех программ; Крякл об этом скажет).
- Это недели работы, не дни.

**Нужно от вас.** Один раз, около 15 минут, по моей инструкции: создать на сайте Apple сертификат подписи и ключ для проверки сборок. Mac для этого не нужен.

## Для исполнения

### Архитектура

- `src/os/api.ts`: интерфейсы системного слоя. `src/os/win.ts` собирает их из нынешних модулей (`winkbd`, `winclip`, `winclipboard`, `uia`, `dwm`, `winshot`, `wincursor`, `ocr`, `system32`, `chrome`, `device`). `src/os/mac/*` — вторая реализация. `src/os/index.ts` выбирает по `process.platform`.
- Готовые швы: `TypistEnv` + `KbdIn/KbdOut` (typist.ts), `ClipboardBackend` (clipguard.ts), `ShotRequest/ShotReply` (shot-worker.ts), `recognize()` → `OcrResult` с несколькими чтениями (ocr.ts), `LlmFiles`, `filesFor` (voicestore.ts; darwin-arm64 уже в манифесте), `speech.ts` (ветка `say` есть).
- Швов нет: main.ts (~75 прямых вызовов), dictation.ts, menuwindow.ts, shotwindow.ts, recordwindow.ts, keyboard.ts → перевести на `os.*`.
- `os.can` (printScreen, pauseKey, panelsInWindow, card, contentProtection, uninstaller…) уходит в `AppView`; страницы прячут и переименовывают по нему. Клавиши: `hotkey.ts hotkeyLabel` + ⌘ ⌥ ⌃ ⇧; `Control+C*2` ↔ `Command+C*2` (`isCopyTwice`); `DEFAULTS` по системе; Ctrl+Space и Fn не предлагать.
- Тест-сторож: импорт `koffi` и `win*` вне `src/os/win*` валит vitest.
- Mac: C-API через koffi (objc_msgSend — отдельный прототип на каждый селектор, без `...`). Перехват клавиш — поток со своим CFRunLoop; все вызовы раскладок (TIS, данные для UCKeyTranslate) только в главном потоке, поток получает готовое состояние и просит переключение сообщением. Swift-помощник (собирается в CI) для Vision.
- Папки Mac: `~/Library/Application Support/Kryakl`, загрузки там же в `Downloads`; `oldfolder.ts` выключен. Идентификатор на Mac `com.ikstro.kryakl`. Минимум macOS 14.

### Шаги

0. **Пробы** (`.github/workflows/mac-probe.yml`, вручную, `macos-15` arm64; `scripts/mac-probes/`): koffi в Electron 45; SIP и запись своей программы в TCC через sqlite3 (Accessibility, ListenEvent, ScreenCapture) — от этого зависит шаг 7; перехват и проглатывание клавиши в потоке, повторное включение после тайм-аута; раскладки из главного потока; выделенное в TextEdit и в Chrome (`AXManualAccessibility`); набор кодами клавиш против юникода; буфер обмена целиком, предупреждения о чтении буфера; активация чужого окна; панель без кражи фокуса (`type: 'panel'`, `showInactive`, `focusable: false`); снимок экранов и список окон; запись MP4, звук системы (14.2+, `NSAudioCaptureUsageDescription`); llama.cpp `macos-arm64` из b11929 на маленькой модели; uv `aarch64-apple-darwin` 0.13.0 + `uv sync` + тесты движка; CTranslate2 `device="mps"`; голос; Vision на ru/uk/en по одному языку за чтение. Результаты в CLAUDE.md.
1. **Системный слой, Windows без изменений**: интерфейсы, `os/win.ts`, перевод вызовов, `os.can`, клавиши по системе, vitest зелёный на Windows и на Mac (убрать зависимость тестов от `\`).
2. **Сборка и подпись**: `electron-builder.yml` `mac:` (arm64, `minimumSystemVersion` 14, `icon.icns`, `LSUIElement`, описания микрофона и звука системы, `build/entitlements.mac.plist` с audio-input и disable-library-validation для голоса); esbuild собирает Mac-потоки. Workflow: `build-mac` (без секретов: тесты, неподписанный `.app`) → `test-mac` (шаг 7) → `sign-mac` (секреты, только инструменты Apple: codesign изнутри наружу, notarytool, stapler, hdiutil с ярлыком Applications) → `.dmg`. `publish` прикладывает dmg к релизу только при включённой переменной репозитория. Секреты: Developer ID Application (.p12; ключ и запрос создаёт openssl на этом компьютере) и ключ App Store Connect.
3. **Ядро**: строка меню (цветной значок по теме) и панель, окна с кружками (`titleBarStyle: 'hiddenInset'`, `html.mac`), Dock только пока открыто окно, просьба перенести в «Программы» при запуске из другого места, шаг «Разрешения» и плашка на Главной (статусы, кнопки в нужный раздел настроек, «включён защищённый ввод» по `IsSecureEventInputEnabled`), буфер обмена (NSPasteboard: снимок, счётчик опросом, метки nspasteboard.org Transient/AutoGenerated/Concealed, возврат по таймеру), Cmd+C/Cmd+V, выделенное через Accessibility с запасным Cmd+C, возврат окна, Быстрый перевод, словарь, голос, llama.cpp Metal в `llm-manifest.json` (вид `metal`), `device.ts`/`hardware.ts`/`resources.ts` для общей памяти (sysctl, свободная память вместо nvidia-smi), Проверка, Разговор.
4. **Речь**: `speechpack.ts` для Mac (`env/bin/python`, без частей NVIDIA; torch с MPS для «Кто когда говорил»), три Windows-вызова в `engine/` (asr.py, jobs.py, settings.py), `models.json` — устройства Mac, печать голосом, плашка диктовки (панель на всех столах и над полным экраном), расширение Chrome (`chrome.ts`, `chromecheck.ts` — пути Mac), записи и встречи.
5. **Клавиатура**: `src/os/mac/kbd-worker.ts` (CGEventTap клавиш и мыши; таблица кодов Mac ↔ коды `Typist`, тесты), раскладки, набор исправления кодами клавиш в нужной раскладке (юникод только где кодами нельзя, по 20 знаков), пометка своих клавиш, поля пароля, значок раскладки у курсора и в строке меню, звуки, программы по имени, меню на одной клавише, запись клавиш в настройках, предупреждения (Punto Switcher, Caramba, Karabiner, «Caps Lock переключает язык», «свой язык у каждого документа»).
6. **Экран**: рамка скриншота (снимок экранов, окна, страница браузера через Accessibility, указатель, копирование картинки и файлов), окно «Скриншоты», текст со снимка (Swift-помощник, чтение на каждый язык → `pickLines`), запись экрана (окно, экран, кусок; микрофон; звук системы; клики и увеличение). Полоска: вне куска; для всего экрана скрыта, стоп по значку в строке меню и по клавише.
7. **Сценарии на Mac-сервере** (`scripts/mac-e2e/`, собранный `.app` с `KRYA_TEST_HOME`, цель — TextEdit; снимки и видео прогона в артефактах): перевод выделенного → Вставить; Cmd+C дважды → карточка и звук; «ghbdtn » → «привет »; клавиша переключения; Pause на выделении; диктовка с поддельным микрофоном → текст в TextEdit; скриншот → PNG в буфере; запись 5 с → файл играет; текст с картинки; `npm run shots` на Mac в трёх языках; `spctl -a -vv`, `stapler validate`, запуск с карантинной меткой. Модели в сценариях маленькие: в 7 ГБ настоящие не помещаются.
8. **Выдача**: страница для тестировщика (установка, разрешения, список «только человек», «Сообщить о проблеме» — `report.ts` для Mac), dmg в предварительном релизе по ссылке, раздел в CLAUDE.md, строки Mac в `docs/backlog.md`. Лендинг («Скачать для Mac», требования, три языка) — после отчётов.

### Проверка

- Каждый шаг: `npm test`, `npm run typecheck` на Windows; то же и пробы на `macos-15`.
- Windows не сломан: `npm run shots` до и после шага 1, установщик запущен на 10 с, шесть сценариев руками у владельца (перевод выделенного и Вставить, диктовка, исправление раскладки, Pause на выделении, скриншот, запись экрана).
- Mac: шаг 7 зелёный, артефакты просмотрены, dmg проходит `spctl`.
- Только человек: настоящие модели и скорость, микрофон, звук системы, два монитора, окна разрешений, первый запуск скачанного файла.

## Решено (владелец, 2026-11-17: «все вопросы как ты рекомендуешь»)

1. Перед рассылкой всем сборку 15 минут пробует один человек («запускается ли вообще»), потом получают остальные.
2. Ребята получают ссылку на предварительный релиз GitHub, на сайте его не видно. Кнопка «Скачать для Mac» на лендинге — после их отчётов.
3. Минимум macOS 14.
4. На Mac в Настройках есть кнопка «Удалить все данные Крякла» (спрашивает один раз, как удаление на Windows): другого способа освободить около 12 ГБ там нет. Входит в шаг 3.
