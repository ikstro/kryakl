# AGENTS.md

Инструкции для Codex и других агентов, работающих в этом репозитории. Применяются ко всему проекту.

## Начало работы и источник контекста

1. В начале новой сессии прочитай [CLAUDE.md](CLAUDE.md). Это общий источник архитектуры, решений владельца и ограничений продукта; его инструкции относятся и к Codex. Если вывод обрезан, дочитай файл частями.
2. Для текущей задачи прочитай соответствующие исходники и разделы [docs/backlog.md](docs/backlog.md). Backlog содержит как сделанное, так и планы и открытые вопросы. Сам по себе он не является поручением реализовать всё перечисленное.
3. Перед изменениями проверь `git status --short` и вложенные `AGENTS.md` в затрагиваемых каталогах. Сохраняй чужие незавершённые изменения.
4. Выполняй текущий запрос пользователя. Если он ссылается на отдельный план, прочитай этот план; не считай открытый в IDE файл автоматически назначенной задачей.

Этот файл дополняет `CLAUDE.md`, а не заменяет его. Ссылки здесь — обычные пути: содержимое связанных документов нужно действительно прочитать.

## Как разрешать противоречия в документации

- В пределах проектных требований текущие явные указания пользователя имеют приоритет.
- `CLAUDE.md` содержит историю, а разделы расположены не строго по времени. Более позднее утверждённое решение владельца заменяет раннее только в той части, где они расходятся. Учитывай пометки `Since`, `replaces`, `over ... where they differ` и даты, а не положение абзаца в файле.
- Различай утверждённое поведение, уже выполненную работу, предложение и вопрос, оставленный владельцу. Планируемую архитектуру не описывай как существующую.
- Команды, версии, пути и фактическую реализацию сверяй с `package.json`, конфигурацией и исходниками. Если код расходится с действующим решением владельца, обозначь расхождение; не отменяй решение молча.
- Краткие ориентиры ниже могут устареть. При расхождении перечитай актуальный раздел `CLAUDE.md`; не создавай здесь вторую независимую историю решений.

## Что за проект

**Kryakl / Крякл** — Windows-приложение в трее на Electron и TypeScript: локальные перевод и чтение, практика английского, диктовка, расшифровка, исправление раскладки, снимки и запись экрана. Речевой движок — локальный Python-сервис в `engine/`.

- Основная обработка выполняется на компьютере пользователя. Загрузка моделей и компонентов предусмотрена продуктом; отправку пользовательских текстов, звука и снимков в облачные сервисы не добавляй.
- Актуальное имя — Kryakl, в украинском и русском интерфейсе — Крякл. Старые имена встречаются в миграциях и совместимости. Сохраняй `KRYA_*`, `X-Krya-*` и `com.ikstro.2talker`, пока задача явно не требует изменения совместимости.
- Локальные LLM уже используются для перевода, Check my English, Talk и опционального редактирования диктовки. Старый общий запрет на LLM читай вместе с этими исключениями; итоги встреч и произвольное переписывание выделения остаются вне принятого объёма.

## Ограничения, которые нужно сохранять

- **Данные и совместимость.** Настройки и списки — `%APPDATA%\Kryakl`, загрузки — `%LOCALAPPDATA%\Kryakl`, расшифровки по умолчанию — `Documents\Kryakl\Transcripts`. Не ломай миграции старых имён и выбранные пользователем папки. Логи и отчёты не должны раскрывать секреты и содержимое пользовательских библиотек.
- **Границы доступа.** Сохраняй ограничения страниц в `bridge.ts`, проверку подлинности локального речевого сервиса, фиксированный origin расширения и авторизацию llama.cpp. Renderer не должен получать произвольный доступ к файлам или привилегированным действиям main.
- **Буфер и клавиатура.** Временные заимствования буфера проводи через `ClipboardGuard`; явное Copy пользователя имеет другую семантику. Сохраняй фокус целевого поля, приватные метки буфера и защиту паролей. Не обучай исправление в неизвестных полях, терминалах и менеджерах паролей.
- **Горячие клавиши.** `Ctrl+C` дважды — назначаемая клавиша действия на выделении, пустая по умолчанию. Pause — пример клавиши исправления, не встроенное назначение. После преобразования выделения курсор остаётся в конце, выделение снимается; повторная клавиша продолжает цикл до ввода или клика.
- **Ресурсы.** Соблюдай контракт в `docs/backlog.md`: чужие программы первыми получают видеокарту, простой освобождает её. Решение от 2026-11-12 требует совместного размещения своих моделей или работы по очереди и отдельного лёгкого пути на процессоре. Часть этого ещё запланирована: перед изменением проверь статус, не возвращай медленное падение карточной модели на CPU как готовое решение.
- **Интерфейс.** Используй существующие токены, Inter, JetBrains Mono, Lucide и принятую структуру страниц. Язык по умолчанию — английский; украинский и русский выбираются явно. Новые строки добавляй одновременно во все три словаря через существующий `t(...)`.
- **Снимки и OCR.** Text в снимке сначала показывает исходные строки и отступы, перевод — по отдельной кнопке. Быстрая команда «Перевести с экрана» переводит сразу. Save As открывается после закрытия рамки. Замена Windows OCR на PP-OCRv5 оставлена владельцу после замеров, не считай её уже утверждённой.
- **Обновления.** Новая версия устанавливается вручную с GitHub. У приложения нет автообновления. Процесс релиза создаёт черновик; публикация остаётся шагом владельца.

## Работа и проверки

Делай изменения в рамках задачи, следуя существующим решениям и стилю кода. При новом утверждённом решении обновляй соответствующее место общей документации; в backlog различай сделанное и оставшееся. Не редактируй сгенерированные файлы вместо их источников.

Команды из корня проекта:

```text
npm run typecheck                 # TypeScript
npm test                          # Vitest, однократный запуск
npx vitest run src/translate.test.ts  # пример точечной проверки
npm run build                     # сборка приложения и webview
npm run test:engine               # Python-тесты, нужна engine/.venv
npm run shots                     # снимки интерфейса, сначала build
node scripts/build-site.mjs       # генерация site/uk/ и site/ru/
node scripts/build-site.mjs --check
```

- Выбирай проверки по изменению: логика TypeScript — соответствующие тесты и typecheck; сборка/IPC/webview — также build; Python — тесты движка. Для исправлений поведения добавляй содержательные регрессионные проверки, где это возможно.
- Для изменений речи сверяйся с `docs/speech-quality.md` и `engine/quality/`; для OCR — с `docs/ocr-quality.md`. Скорость и качество подтверждай измерениями, различая автоматические и ручные проверки.
- При изменении интерфейса проверь внешний вид, обе темы и затронутые языки. `SHOTS_LANG=uk|ru` и `SHOTS=daily|tray|card` поддерживаются скриптом снимков; в PowerShell задавай их через `$env:...`.
- Для изменений только документации достаточно проверить содержание, ссылки и diff; сборка и тесты приложения не нужны.
- Перед запуском Electron убери `ELECTRON_RUN_AS_NODE` из окружения запуска, если он установлен. У приложения единый single-instance lock: тестовый запуск тоже требует завершения установленного Kryakl. Для ручной проверки используй отдельный `KRYA_TEST_HOME` и при необходимости `KRYA_TEST_PORT`, учитывая правила запуска из `CLAUDE.md`.
- В итоговом ответе кратко укажи, что изменилось, что проверено и какие проверки остались невыполненными. С пользователем общайся на языке его запроса; язык разговора не меняет язык интерфейса продукта.
